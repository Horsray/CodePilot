# Upstream 差距调研：v0.54.0 → v0.67.17（30 个版本）

> 调研时间：2026-10-06 · 数据来源：GitHub Releases（op7418/CodePilot，30 个版本完整 Release Notes）

## 一、演进主线

上游从「多引擎聊天客户端」转向「以助理/工作区为中心的多 Runtime 个人 AI 平台」，分三段：

1. **0.55–0.60 立引擎与编排**：三 Runtime（CC/Native/Codex 全局+按会话切换）、多模型 Sub-agent 编排（依赖工作流）、模型/渠道爆发（Fable 5、Grok 4.5、通用 OpenAI 兼容等）
2. **0.61–0.65 立资产与助理**：Harness 统一配置模型（Memory/Skill/MCP/Runtime）、素材库+网页归档、心跳助理（HEARTBEAT.md）、记忆读写格式三 Runtime 统一
3. **0.66–0.67 信任与工程基建**：Provider Key 加密、崩溃自愈、数据库恢复、签名自动更新、遥测隐私；UI 收敛为统一侧栏+内置浏览器；模型接入演化为「会话绑定 Runtime + 可解释用量」

## 二、⚠️ 先处理的风险：更新检查指向 upstream

`src/app/api/app/updates/route.ts:5` 硬编码 `GITHUB_REPO = "op7418/CodePilot"` —— 应用内"有新版本可用 v0.67.17"提示的是**官方版本**，点"下载推荐版本"会下载官方 DMG。虽然 `electron/updater.ts` 已禁用原生自动更新（不会静默覆盖），但**用户手动安装官方包将丢失全部 fork 定制**（CC Switch、媒体中转、cc-haha UI、Git 增强等）。

**建议**：要么把该常量改指向 fork 仓库（Horsray/CodePilot），要么在弹窗文案中明确标注"官方版，安装将覆盖本 fork 定制"。改指向 fork 后需在 fork 的 release 里维护 latest-mac.yml 等资产。

## 五、建议的同步策略

**不做整体 merge**（UI 层与 provider 层已彻底分叉，全量合并冲突面过大）。采用：

1. **按功能点摘取**：用 `gh` 拉取目标版本的 commit/diff，只挑安全、稳定性、性能类文件（多在 `src/lib/`、服务端 API、`electron/` 层，冲突面小）
2. **模型/渠道清单单独移植**：更新模型目录、参数矩阵、渠道预设（收益快、风险低）
3. **每吸收一项跑一次 `npm run test` + 冒烟**，涉及 UI 的项额外 CDP 验证
4. **登记到 `fork-patches.manifest.json`**，避免下次同步重复判断
