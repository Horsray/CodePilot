# 为什么把 cc-haha 的界面与流式体验移植进 CodePilot

> 技术实现见 [docs/handover/cc-haha-ui-port.md](../handover/cc-haha-ui-port.md)

## 用户问题

1. **流式输出"一坨一坨"**：CodePilot 的回复不是平滑地逐字出现，而是卡顿 2.5 秒后整段闪现，长回复尤为难受。中文用户感受最强烈——因为扣留逻辑按"空格分词"计数，中文永远不达标。
2. **界面观感**：同期维护的 cc-haha 视觉更精致（卡片式布局、柔和的亮暗配色、克制的圆角与阴影、自托管字体），希望把"那套感觉"整体搬过来，而不是零敲碎打地改。

## 为什么选择"移植"而不是"重做"

- 两个应用的产品形态几乎同构（都是 AI Agent 桌面客户端），cc-haha 的组件层级与 CodePilot 一一对应，移植成本远低于从零设计。
- cc-haha 的令牌体系是 Tailwind v4 CSS-first（`@theme` + 语义变量），天然适合整体搬运；CodePilot 的 shadcn 命名可以映射到同一套值，**存量页面零改动换肤**——这是"全量移植"能在一次迭代内完成的关键。
- 流式体验选择照搬 cc-haha 的三级节流（渐进揭示 + 批量 flush + thinking 降频），因为它在 cc-haha 的真实使用中已被验证；而不是在 CodePilot 里重新发明一套。

## 关键设计取舍

1. **流式期间不解析 Markdown**：cc-haha 在流式阶段只渲染纯文本，结束后才切成完整 Markdown。这与"边流边看到排版"的直觉相反，但换来的是长文本不掉帧、不跳版。取舍理由：掉帧的伤害大于"晚几秒看到排版"。
2. **移除 13 套主题家族**：多主题是 upstream/早期 fork 的特性，但与 cc-haha 的单套亮/暗语言冲突（每套主题都要适配新组件，维护成本线性增长）。明确降级为"亮/暗/跟随系统"三态，保证视觉一致性优先。
3. **渐进揭示只作用于展示层**：`accumulatedText` 始终是全文，`revealedLength` 只影响快照里展示的内容；工具事件、流结束、出错都会立即冲刷。这样"平滑"永远不会拖慢真实完成时间。
4. **布局从"悬浮面板"改为"停靠卡片"**：cc-haha 的观感很大一部分来自"整个应用是一张浮在底色上的画布"；CodePilot 原来的悬浮侧栏 + 通栏顶栏是另一种语言，不换骨架，换肤效果会打折。

## 未来方向

- 工具调用时间线卡片（ToolCallBlock/ToolCallGroup）可继续按 cc-haha 的样式深挖（渐变连接线、折叠动画、diff 徽标）。
- 侧边栏收起可升级为 cc-haha 的 72px rail（图标模式），工具类已就位。
- 若未来 upstream 继续演进多主题家族，需要在同步时明确"不恢复"——已写入 fork-patches 清单。

## 已知局限

- 流式纯文本阶段会短暂显示 Markdown 符号（`#`、`**` 等），完成瞬间切换为排版；这是 cc-haha 同款行为。
- 暗色模式仍有少量历史组件使用中性灰（文件图标等），属可接受的语义色。
